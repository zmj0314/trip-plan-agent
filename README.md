# 行程档案 · Travel Dossier

把「我从某地想去某地」变成**可执行的多段行程**的 Agent。
**先问清 → 出计划 → 等同意 → 流式执行**，覆盖门到门（家门口 → 同城 → 城际 → 接驳）。

非商业个人项目。**付款永不自动发生** —— 框架只准备参数，支付始终由用户在官方渠道完成。

---

## 快速开始

```powershell
# 1. Python 环境
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# 2. 前端依赖
cd web; npm install; cd ..

# 3. MCP 服务端装到项目本地（见下方「为什么不用 npx」）
.\scripts\install-mcp.ps1

# 4. 启停
.\scripts\dev.ps1        # 起后端 + 前端，等健康检查通过后打印地址
.\scripts\stop-dev.ps1   # 停
```

打开 **http://127.0.0.1:5173**。

> **服务必须在沙箱/受限环境之外启动。** 12306 的 MCP 是一个子进程；
> 受限环境会拦掉进程派生，表现为 `server closed stdout`，然后静默回退到公路方案。

### 配置模型（可选）

不配也能跑：所有外部数据源都是**免密钥**的，未配置模型时使用离线规则桩。

打开页面 → 右侧「模型」→ 选 **DeepSeek 云端** 或 **本地 llama.cpp** → 粘贴密钥 → **点「测试连接」**（会真调一次模型）。

`llama-server` 本身就是 OpenAI 兼容接口，所以本地模型不需要额外适配层：

```bash
llama-server -m your-model.gguf --port 8080
```

## 现在还不能做什么

- **中转查询**：`get-interline-tickets` 已注册为能力，但规划器还没用它 —— 无直达车次时不会自动串中转
- **景点内容还是骨架**：候选点来自地名解析，没有评分/门票/开放时间（`poi.discover` 目前返回未归一化载荷，需先补 HTTP 归一化）
- **餐饮只给"就近建议"**：真实餐厅 POI 待 `poi.food` 打开
- **住宿只有区域建议**：`poi.stay` 实时房价待 F2
- **`D3 · CLOCK.TODAY`**：日期锚点在 MCP 不可用时降级，不影响规划但优先级偏低
- **评分可能为负**：惩罚项可以超过加权和（数学上自洽），但界面没有解释，看起来像出错
- **只比较驾车/骑行/步行的公路方案**，公交/地铁未接入
- **导出没有 PDF**：markdown / txt / html 三种离线格式；PDF 需要新依赖，属部署选择
- **分享是文件不是链接**：单用户本地应用没有鉴权与托管，公开链接需要存储与撤回机制，v1 明确不做
- **流式只覆盖渲染类节点**：`intake` / `clarify` 这类抽取节点不流式（把半成品 JSON 展示给用户是噪音）；流式文本是原始 JSON，节点结束后由渲染文案替换
- **浏览器站点选择器未实测**：`app/browser/sites.py` 里的 12306 选择器写自文档结构、**从未对真实页面验证**，因此余票结果带 `selectors_verified: false`；选择器失效时会明确报"结果表未出现（选择器可能已变更）"，而不是把读到的任何东西当答案
- **景点预约流程未实现**：`read_reservation_status` 明确返回 UNAVAILABLE，而不是猜一组选择器
- **景点内容富化待 amap key**：`poi.detail` 的归一化代码可以按官方字段写，但字段名必须用真实响应验证后才敢写死
- 打车仍依赖浏览器兜底，尚未实现

## 为什么不用 npx 启动 MCP

从长期运行的服务里拉 `npx` 在 Windows 上不可靠，三个变量叠加：

1. `npx.CMD` 是**批处理垫片**，`CreateProcess` 不直接执行批处理
2. 路径含**空格**（`C:\Program Files\nodejs\npx.CMD`）
3. 服务进程是隐藏窗口 + 重定向输出，**没有控制台**

实测结果：同一份代码，独立进程三次全成功，API 进程三次全失败。

所以 `scripts/install-mcp.ps1` 把包装进 `var\mcp\`，运行时用 `node <entry>` 直接启动。
**一次消掉三个变量，顺带把版本钉死。** `npx` 仍然保留为兜底路径。

### 几条不能破的原则

| 原则 | 含义 |
|---|---|
| **语义归 LLM，裁决归代码** | 闸门、打分、约束校验、风控、幂等全部是确定性代码 |
| **边界归代码** | 不给出通道，而不是命令不要做 |
| **计划即版本** | 同意绑定计划哈希；计划一变，旧同意立即失效 |
| **副作用必幂等** | 幂等键由业务指纹派生（**剥掉每次重规划都会变的 id**），唯一约束建在数据库层 |
| **降级是一等公民** | 每个能力预先声明降级阶梯，失败必须可解释 |
| **副作用不可降级** | 降级档算 `ok`，所以「没执行成功」绝不能降级成「自助去做」——那是把失败说成成功 |
| **模型说的话要当成不可信输入** | 真实模型会输出 `return_by` / `self_arranged` / `"2026-09-12 当天返回"`；闸门必须能认出它们，认不出就要问，而不是静默卡住 |

### 安全

- 凭证只进环境变量与请求头，**不落库、不进图状态、不进日志**
- 实名信息不持久化
- `payment.*` 能力**不存在**：不是靠策略拦截，是注册表里根本没有

### 浏览器通道怎么开

```powershell
# 用你日常的 Chrome 打开调试端口（复用登录态），再启动本项目
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222
```

不启动也没关系：`browser.*` 全部报告 **UNAVAILABLE**，能力链会落到下一个 provider（例如 12306 余票落到 MCP 搜索）。
**这是设计行为，不是故障** —— 但也是为什么浏览器通道必须排在 12306 之后。

一条硬规则：**「工具返回『已点击』不算数，页面真的动了才算」**。
每个会改变页面的调用都必须在 `expect` 里声明验收条件（页面文本/元素出现/元素消失/URL/页面变化），
adapter 会在动作**前后各观察一次页面**并按条件校验；不满足就是 `ERROR`，不是"成功但有个小提示"。
